## Analysis

**Setup.** 3 queries from `configs/lab_default.yaml`, run through `baseline` (single LLM
call, no tools) and `multi-agent` (supervisor → researcher → analyst → writer → critic),
both on `nvidia/nemotron-3.5-lightning:free` via OpenRouter.

**Latency/cost vs. quality tradeoff.** Multi-agent averages ~244s vs. baseline's ~26s —
about 9.5x slower, because it makes 3-4 sequential LLM calls per query instead of 1, plus a
real web search. Cost is 0 for both (free-tier model), so in a paid-model deployment this
latency gap would translate directly into a proportional cost gap. In exchange, the quality
proxy rises from 6.5 to 8.5 (out of 10) and multi-agent produces real citations (baseline has
none — it never calls a search tool, so `citation_coverage` is undefined/`None` for it by
design). This matches the lab's core question: multi-agent is worth the latency/cost overhead
specifically when the task benefits from independent source-gathering and verification, not
as a default upgrade over a single LLM call.

**Failure mode: citation coverage below target (multi-agent · q3).** The critic flagged
q3's final answer for citation coverage (36%, below the 50% target). Root cause, found by
inspecting the raw state trace: the writer model sometimes emits citation markers as
markdown-escaped `\[1\]` instead of plain `[1]`. During this benchmark run the citation
regex only matched plain brackets, so a well-cited answer (q1/q2, also written by the same
model) was scored as having near-zero coverage — a **measurement bug**, not necessarily
a real writing defect. This was caught live and fixed in
`evaluation/benchmark.py`/`agents/critic.py` (regex now accepts an optional backslash around
each bracket); the numbers in this table were generated by the unfixed code, so this is
reported here as a worked example of the exact failure class the fix addresses, not a residual
issue. **Fix applied:** `_CITATION_RE` now matches `\\?\[(\d+)\\?\]`. **Residual risk:** the
citation-coverage metric is still a sentence-level heuristic (fraction of sentences containing
a citation marker), not a semantic check that the citation actually supports the sentence's
claim — a stronger fix would have the critic (or a separate LLM judge) verify that each cited
source snippet actually entails the claim next to it.
